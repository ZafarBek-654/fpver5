# Birga — mysiteprojectfinal (Benefit.uz · Aloqa.uz · Помощь · Игры)

Один сайт из четырёх приложений + админ-панель. Работает на любом статическом хостинге.

## Быстрый старт «с нуля» (≈15 минут)

### 1. Firebase (общая база для всех устройств)
1. https://console.firebase.google.com → **Add project** (Google Analytics можно выключить).
2. **Authentication → Get started → Sign-in method → Email/Password → включить → Save.**
3. **Firestore Database → Create database** → Production mode → любая ближайшая локация.
4. В Firestore открой вкладку **Rules**, удали всё, вставь содержимое файла `firestore.rules` → **Publish**.
5. **⚙ Project settings → Your apps → Web (`</>`)** → зарегистрируй приложение (Hosting НЕ включай) → скопируй блок `firebaseConfig`.

### 2. Создай `firebase.js` (руками ничего править не надо)
1. Открой файл **`setup.html`** в браузере (двойной клик).
2. Вставь скопированный блок из Firebase → **«Проверить и создать firebase.js»**.
3. Исправь всё, что подсвечено красным (там написано что нажать), и снова нажми кнопку.
4. Нажми **«Скачать firebase.js»** и положи файл в папку сайта вместо старого.

### 3. Выложи сайт
**GitHub Pages:** новый публичный репозиторий → Add file → Upload files → перетащи ВСЕ файлы из папки (не саму папку и не zip) → Commit → Settings → Pages → Deploy from a branch → `main` / `(root)` → Save. Через 1–2 минуты появится ссылка. `index.html` должен лежать в корне.
Другие варианты: Cloudflare Pages (Upload assets), Netlify (Deploys → перетащить папку), Firebase Hosting.

### 4. Разреши адрес сайта
Firebase → **Authentication → Settings → Authorized domains → Add domain** → адрес сайта без `https://` и без пути (например `логин.github.io`). Для Firebase Hosting это не нужно.

### 5. Стань владельцем
Сразу после запуска **зарегистрируйся на сайте первым — ты автоматически станешь Преадмином** (сделай это раньше, чем кто-либо ещё). Админ-панель: `/admin.html`.
Проверка: открой `setup.html` на живом сайте — блок «Статус сайта» должен быть зелёным.

## Режимы базы
- **Без Firebase** (пока в `firebase.js` стоит `YOUR_API_KEY`) сайт использует встроенную демо-базу в браузере — всё работает, но данные не общие. Виден значок «Демо-база».
- **С Firebase** данные общие для всех устройств, права проверяет сервер (`firestore.rules`).

## Роли
- **Пользователь** — цены, ссылки, чаты, игры, заявки в помощь
- **Продавец** — + добавляет товары и цены, меняет и удаляет свои
- **Админ** — + блокирует/удаляет предложения и товары, баны, ответы на заявки, чат админов
- **Преадмин** — + назначает и снимает админов, оценки админам

## Benefit.uz: демо и настоящие товары
Пока нет настоящих товаров, виден 5 демо-товаров (помечены «ДЕМО»). Как только продавец или админ добавит первый товар («Мои цены» → «Добавить товар»), демо исчезают.

## ИИ-агент
По умолчанию — встроенный базовый режим. Для настоящего Claude разверни `ai-worker.js` на Cloudflare Workers (ключ хранится в секретах Worker), адрес вставь в `BIRGA_AI_URL` внутри `firebase.js`.

## Если что-то не работает
Открой `setup.html` на живом сайте — он покажет причину красной строкой. Частые причины: не опубликованы правила, выключен Email/Password, адрес сайта не добавлен в Authorized domains, на хостинг загружен старый `firebase.js`.

## Ограничения
Телефон/email не подтверждаются; рекорды в играх пишет браузер; список пользователей читается целиком (для тысяч пользователей нужна пагинация).
